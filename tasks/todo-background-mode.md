## Phase 3 — Restart survival + logging
- [x] **Task 13** *(Model: Sonnet 5)* — `gui.py`: auto-resume on app launch from persisted state (mid-download, backoff-pending future/past, done/absent cases). Re-derives against a fresh library scan rather than trusting stale persisted state blindly. One-shot check (`_pending_background_resume_check`) fires from `_on_library_scanned` exactly once per session, after the first post-startup scan. `_maybe_resume_background` no-ops on missing state, a `songs_folder` mismatch, or `phase == 'done'`; dispatches to `_resume_background_library_tools` (re-runs the Library Tools pass only) or `_resume_background_downloading` (re-derives remaining targets as `fresh_scan ∩ remaining_folders ∩ not has_video`, skips to Library Tools if that's empty, otherwise cancellably waits out any future `resume_at` on a worker thread before bouncing back via `self.after(0, ...)` to `_finish_resume_and_launch`, which resets `self._running = False` before calling `_launch_background` — required so `_launch_background`'s own `if self._running: return` guard doesn't silently no-op the resume).
